## Architecture notes (supersede AGENTS.md where they conflict)

- **AI calls are server-side, not client-side.** `google_generative_ai` and `flutter_secure_storage` were removed from `pubspec.yaml`. The app calls a Firebase Cloud Function (`chatWithTutor` in [functions/index.js](functions/index.js)) via `cloud_functions`, and the Gemini API key lives in a Firebase secret (`geminiApiKey`), never on-device. Ignore the AGENTS.md line about reading API keys from `flutter_secure_storage` — that flow no longer exists.
- **Multi-bot chat system.** [lib/features/ai_chat/models/ai_bot.dart](lib/features/ai_chat/models/ai_bot.dart) defines 10 subject bots (planner, math, english, programming, physics, chemistry, history, exam, focus, career). Each bot's `id` must stay in sync with the `botPrompts` map in `functions/index.js` — the id round-trips through `botId` on the chat request.
- **Account deletion** is a Cloud Function (`deleteAccount` in `functions/index.js`): wipes `assignments`, `timetables`, `ai_chats/{uid}/messages`, the `ai_chats/{uid}` and `users/{uid}` docs, then deletes the Firebase Auth user. Called from the settings screen.
- **App identity migration in progress.** Android package is moving from `com.example.eduplanner_ai` to `com.eduplanner` (new Kotlin source dir + `google-services.json` already added; old `MainActivity.kt` under `com.example.eduplanner_ai` was deleted). App icon is now generated via `flutter_launcher_icons` from `assets/images/app_icon.png` (dark `#0B0B1E` adaptive background) — regenerate with `flutter pub run flutter_launcher_icons` after changing that source image, don't hand-edit the icon files.
- iOS has a real `GoogleService-Info.plist` now (was missing/placeholder before).
- **Study groups (class-wide sharing).** New `lib/features/groups/` feature + `study_groups` Firestore collection. Joining a group is server-side only — `joinGroupByCode` in `functions/index.js` uses admin privileges to add the caller to `memberIds`, because Firestore rules only let *existing* members update a group doc (a joiner isn't one yet). `ClassModel.groupId` (nullable) marks a timetable entry as shared; `TimetableNotifier.addClass` auto-attaches the caller's current group id. In a group, `TimetableRepository.watch`/`slotOccupied` use the union of the caller's own classes (`userId`) and the group's (`groupId`), de-duplicated by id (changed 2026-10-13; before, personal classes vanished on joining). Only the original creator (`userId`) can edit/delete a class entry; other members can read it (`isGroupMember()` in `firestore.rules`) and may update only `status`/`statusNote`/`statusDate` (休講/変更 reports).
- **Cancellation/change alerts.** `ClassModel` gained `status` (`normal`/`cancelled`/`changed`), `statusNote`, `statusDate`. Reporting a status (via `class_detail_sheet.dart`'s "休講・変更を報告" sheet) only shows a banner locally *unless* the class is shared — `onClassStatusChanged` (a `firestore/v2` `onDocumentUpdated` trigger in `functions/index.js`) fires on write and pushes an FCM notification to every other group member using the `fcmToken` already stored on each `users/{uid}` doc by `NotificationService.initialize()`. `statusDate` is the date of the affected class occurrence (`nextClassDate()`), not the report time; `ClassModel.statusAppliesTo(day)` gates the UI per displayed date.
- **Quiz auto-generation.** New `lib/features/quiz/` feature calls `generateQuiz` (Cloud Function) which prompts Gemini for structured JSON (5 MC questions), not a chat reply — parsed with a markdown-fence strip before `JSON.parse`. Entry point is the "テスト" pill button in the AI chat header (`_QuizButton` in `ai_chat_screen.dart`), pushing `/quiz`.
- **Weak-area analysis.** `home_provider.dart`'s `weakAreaProvider` aggregates per-subject assignment stats (total/completed/overdue/avg difficulty) locally — no AI needed for the counting — then sends just those numbers to `analyzeWeakArea` (Cloud Function) for a short Gemini-written Japanese summary. Cached per-day in `SharedPreferences` (same pattern as `aiStudyTipProvider`), shown via `WeakAreaCard` under the AI tip card on Home.
- **AI privacy: minimal payloads only.** `chat_repository.dart`'s `chatWithTutor` call sends only `{subject, dueDate, status, progress}` per assignment and `{subject, dayOfWeek, period}` per class — no assignment title/description (may hold personal notes) and no teacher names (third-party data) leave the device. Never widen these payloads without re-checking whether the added field is actually needed.
- **Assignment subject field is free text, not a fixed dropdown.** `add_edit_assignment_sheet.dart` uses the same `Autocomplete`-over-`AppInputField` pattern as `add_edit_class_sheet.dart` (suggestions from `SubjectColors.all` + the student's own timetable subjects via `timetableStreamProvider`, but any text is accepted). `SubjectColors.of()` already has a neutral `_fallback` style for names outside the fixed 6, so custom subjects render fine everywhere.
- **AI assignment check (課題の自動チェック).** `AssignmentModel` gained `aiCompletionPercent`, `aiMissingParts`, `aiAdvice`, `aiAnalyzedAt`. From `assignment_detail_sheet.dart`'s "課題をアップロードしてAIチェック" button, `file_picker` (`withData: true` — required for the bytes to be populated on web/desktop, not just mobile) picks an image/PDF/`.docx`/`.txt`, which `AssignmentsNotifier.checkWithAi` base64-encodes and sends to `analyzeAssignmentSubmission` (Cloud Function). That function feeds images/PDF to Gemini natively via `inlineData`; `.docx` is extracted to plain text server-side with `mammoth` first (Gemini has no native Word support), `.txt` is read directly. **The uploaded file is never written to Storage or logged** — it exists only in the function's memory for that one call, matching the "no raw submission persisted" privacy choice; only the derived result (percent/missing parts/advice) is written to Firestore. Server-side caps: 10MB file size, extracted text truncated to 6000 chars, mimeType allow-list. Result renders via the existing `DonutChart` shared widget.
- **Cross-platform note.** `flutter build web` and `flutter build linux` both compile clean as of this session (see work log below) — this app is not mobile-only in practice even though AGENTS.md says "Target: iOS + Android." Any new plugin (like `file_picker`) must be used through APIs that behave the same across platforms — e.g. always pass `withData: true` and read `PlatformFile.bytes`, never assume a real filesystem `path` (web has none).
- **Timetable day tabs now show real calendar dates** (`day_tab_row.dart` takes a `weekStart` param), with prev/next week navigation in `timetable_screen.dart` (`_WeekNavigator`). Classes themselves are still a recurring weekly template with no date field, so switching weeks changes only the displayed dates, not which classes appear.
- **AGENTS.md's "Design tokens" section is stale for the *dark* palette — ignore it there.** The dark palette in [lib/core/theme/app_colors.dart](lib/core/theme/app_colors.dart) is a "Dark Neon" purple/violet theme (`primary = 0xFF7C3AED`, dark backgrounds `0xFF050508`/`0xFF08060F`), not the light indigo palette (`primary = 0xFF4F46E5`) AGENTS.md lists for dark mode. This was true from the initial commit, not a regression — `test/core_smoke_test.dart` was asserting the stale AGENTS.md value and failing until fixed on 2026-07-30. Always read `app_colors.dart` directly for real color values. (AGENTS.md's palette values *are* now used, almost verbatim, as the real **light**-mode palette — see below.)
- **Light theme is real now, via mutable `AppColors` statics, not `Theme.of(context)`.** `AppColors`'s surface/text/subject-text tokens (`background`, `surface`, `surfaceVar`, `bgInput`, `bgLayer`, `bgDeep`, `textPrimary`, `textSecondary`, `textMuted`, `border`, `borderLight`, and the 6 subject `*Text`/`*Dot` pairs) are `static Color` fields, not `static const`, and get reassigned by `AppColors.applyBrightness(Brightness)`. Brand/accent colors (primary, status colors, subject *fills*, gradients) stay constant across themes on purpose — only the neutral surface system flips. `app.dart` resolves the effective `Brightness` from `themeMode` (`MediaQuery.platformBrightnessOf(context)` for `ThemeMode.system`), calls `applyBrightness()` **before** building the widget tree, and keys `MaterialApp.router` with `ValueKey(resolvedBrightness)` so a theme change forces a full remount — every screen's `build()` re-runs and picks up the new static values. Trade-off accepted deliberately: switching theme resets in-progress scroll/form/animation state on the currently-visible screen (GoRouter's own navigation *location* is preserved, since the `GoRouter` instance itself isn't recreated, only the widget subtree under it). This was the deliberately chosen cheaper alternative to threading `Theme.of(context)` through ~370 existing call sites across 43 files.
- **Any style/color that derives from `AppColors`'s mutable tokens must be a getter, not a `static const`.** `AppTextStyles` (in `app_text_styles.dart`) and `SubjectColors` (in `subject_colors.dart`) both learned this the hard way — their text-colored styles are `static TextStyle get` (or, for `SubjectColors._map`/`_fallback`, `static Map`/`SubjectStyle get`) that rebuild a `const`-base style and `.copyWith()` the current color in, rather than baking a color in once. If you add a new derived style/constant that reads `AppColors.textPrimary` (or any of the other mutable tokens) or `SubjectColors.of(...)`, it must follow the same getter pattern or it will either be stuck at whatever color was current at first access, or fail to compile in a `const` context.
- **`ResponsiveBody` now has a 3rd (desktop) tier.** `context.screenSize` (`compact`/`medium`/`expanded`, breakpoints in `Breakpoints`) was defined but unused before this session. `ResponsiveBody.expandedMaxWidth` (default `maxWidth * 1.3`) now kicks in at `ScreenSize.expanded` (>=1200dp — an actual desktop window, not just a tablet), so a real desktop monitor gets a noticeably wider centered column instead of the same tablet-tuned width with huge empty margins. `AppShell`'s tablet/desktop side-rail split is still a binary `context.isTablet` check (600dp) — untouched, still correct, just doesn't itself distinguish tablet from desktop (only the content-width clamp does, via `ResponsiveBody`).
- **No hardcoded English UI strings by design** (AGENTS.md: "all user-visible strings in Japanese"). A few had leaked in over time (bot names in `ai_bot.dart`, nav labels in `app_bottom_nav.dart`/`app_nav_rail.dart`, stat pill labels in `stats_row.dart`, section overlines in `home_screen.dart`/`timetable_screen.dart`/`assignments_screen.dart`, "LIVE"/"Online" badges) — all now Japanese. "AI" alone is kept as-is (a loanword written as-is in real Japanese text); the app name "EduPlanner AI" is a brand name, also left alone. If you add a new label/badge/overline, check it's Japanese before committing — nothing enforces this automatically.
