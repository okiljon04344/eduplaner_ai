# 学校時間割連携 設計書（案）

作成日：2026-10-27　状態：承認済み（2026-10-27、§13 の5〜7は後日確認）　対象：EduPlanner AI

---

## 1. 目的

- 学校がすでに作っている時間割ファイル（Google Drive 上の Excel）を、**そのまま**アプリの情報源にする。教員・教務の作業を増やさない。
- 学生は**何も入力しない**。学校の Google アカウントでログインし、学年とコースを選ぶだけで、自分のクラスの時間割が表示される。
- 時間割の変更（休講・教室変更など）は、学校ファイルの更新を**毎日 8:00 と 17:00** に確認し、変わったクラスの学生だけに通知する。
- ファイルに書けない急な変更や課題・お知らせのために、**教員が入力する画面**を用意する。
- 学生が自分で授業を追加する今の機能（手入力）は残す。

## 2. 範囲と段階

| 段階 | 内容 | 情報源 |
|---|---|---|
| **第1段階（MVP）** | 学校の時間割ファイルを取り込み、学生アプリに日付つきで表示。変更を通知 | 学校の時間割 Excel |
| **第2段階** | 教員入力画面：休講・教室変更・補講・メモ、課題の配布、お知らせ。教員の権限管理 | 教員入力（アプリ／PC） |
| **第3段階** | 年間予定表など、学校で作られる他のファイルの取り込み。他校への展開 | 年間予定表 など |

第1段階は、まず自校（`ihit.ac.jp`）の形式だけに対応する。

## 3. 用語

- **学校ドメイン**：学校の Google アカウントのメールのドメイン（例：`ihit.ac.jp`）。学校を識別するキーにする。
- **クラス**：学年 × コース（例：1年・農業、2年・観光）。
- **コマ**：90分の授業枠。ファイル上は「1・2限目」のように2限を1コマで書いている。
- **学校データ**：時間割ファイルから取り込んだ授業。
- **教員入力**：教員が画面から入力した変更・課題・お知らせ。
- **手入力**：学生が自分で追加した授業（今の機能）。

## 4. 全体構成

```
 学校の Google Drive（ドメイン内共有）
   └ 2026年度 後期時間割.xlsx  ← 教務・教員が今まで通り編集
          │ ①連携（1回だけ、ドメイン内のだれか1人が許可）
          ▼
 Cloud Functions（asia-northeast1）
   ├ syncSchoolTimetable：毎日 8:00 / 17:00（JST）
   │    ダウンロード → 解析 → 前回と比較 → Firestore 保存 → 変更があったクラスに通知
   └ 教員入力の保存時：その場で通知
          ▼
 Firestore（schools / school_days / school_overrides / …）
          ▼
 アプリ（学生）：学校ドメインでクラスを判定し、日付つき時間割を表示
 アプリ／PC（教員）：第2段階の入力画面
```

## 5. 学校の識別と役割

### 5.1 学校の判定
- Google でログインしたときのメールアドレスのドメインで学校を判定する（Google が確認済みのメールのみ）。
- Firestore のルールでも `request.auth.token.email` と `email_verified` でドメインを確認し、他校のデータは読めないようにする。
- Gmail など学校以外のアカウントは、今まで通りの手入力モードで使える。

### 5.2 学校名
- ドメインから学校名を自動で取る公開の仕組みはない（調査済み）。最初に連携した人が学校名を入力し、`schools/{domain}` に保存する。

### 5.3 役割

| 役割 | できること | 決め方 |
|---|---|---|
| 学生 | 自分のクラスの閲覧、手入力、課題の進み具合 | 学校ドメインのアカウント（既定） |
| 教員 | 教員入力（第2段階） | 学校管理者が教員のメールを登録 |
| 学校管理者 | ファイル連携、学校名・コマ時刻の確認、教員の登録 | 検証期間は開発者本人（学校アカウント）。運用開始時に教務の先生へ引き継ぎ、開発者は外れる |

- 自校では学生のアドレスが `s` ＋ 数字、教員が `名前@` の形に見えるが、形だけで教員と判断するのは危ないため、**登録制**にする（形は登録画面での候補表示にだけ使う）。

## 6. 時間割ファイルの連携（第1段階）

### 6.1 方式の比較

ファイルは「ドメイン内のユーザーのみ閲覧可」で共有されているため、Firebase のサービスアカウント（ドメイン外）では読めない。

| 方式 | 内容 | 判断 |
|---|---|---|
| A. 学生それぞれが自分の権限で読む | 全学生に Drive の許可を求める。端末のバックグラウンド実行は不安定 | 不採用 |
| **B. ドメイン内の1人が1回連携し、サーバーが読む** | 学生は何もしない。8:00/17:00 の同期と通知が確実 | **採用** |
| C. 学校内の Apps Script が送る | Google の審査が不要だが、教員がスクリプトを設置する必要がある | 管理者がアプリ連携を禁止している場合の予備 |

### 6.2 権限（スコープ）
- `drive.file` を使う。利用者が選んだファイルだけにアクセスでき、Google の分類で「非機密」のため、簡単な確認だけで公開できる。
- `drive.readonly`（Drive 全体の読み取り）は「制限付き」で、サーバーに保存する場合は有料のセキュリティ審査が必要になるため使わない。

### 6.3 連携の流れ
1. 管理者が PC のブラウザで連携ページ（Firebase Hosting）を開き、学校アカウントでログインする。
2. Google のファイル選択画面で時間割ファイルを選ぶ。
3. サーバーがそのファイル用の更新トークンを `school_secrets/{domain}` に保存する（アプリからは読み書き不可）。
4. すぐに1回同期して、取り込み結果（クラス数・週数・コマ時刻）を画面に表示し、管理者が確認する。

連携した人が卒業・異動した場合は、別の管理者がもう一度連携する。期限切れや失敗は管理者に通知する。

## 7. 時間割ファイルの形式と解析

### 7.1 ファイルの形（2026年度 後期）
- 1週ごとのブロックが縦に並ぶ。各ブロックの左半分が **1年生**、右半分が **2年生**。
- ブロックの見出し行：`1年生 | 月曜日 … 金曜日`、次の行に日付（`10月26日` …）。
- コマ：`１・２限目 09：00～10：30`、`3・4限目 10：40～12：10`、`5・6限目 13：10～14：40`、`7・8限目 14：50～16：20`、間に `休憩`。
- 各コマにコースが2行ずつ：**農業**、**観光**。1行目が科目名、2行目が `担当【教室】`。

例（名前は仮）：

| コマ | コース | 月 | 火 |
|---|---|---|---|
| 1・2限目 09:00～10:30 | 農業 | IT概論2 | |
| | | 田中【104】 | |
| | 観光 | IT概論2 | 簿記2 |
| | | 田中【104】 | 鈴木【102】 |

### 7.2 解析ルール
- 文字は NFKC で正規化する（全角数字・全角括弧・全角コロン）。
- 年度：`2026年度 後期` から、9〜12月は 2026年、1〜3月は 2027年とする。
- コマの時刻は見出しの文字から読み取り、`schools/{domain}.periods` に保存する（アプリ内の固定時刻は使わない）。
- `担当【教室】残り` → 担当・教室・メモに分ける（例：`田中【101】企業説明会` → メモ「企業説明会」）。
- 状態の判定：

| 書き方の例 | 状態 |
|---|---|
| 科目名＋担当【教室】 | 通常 |
| `休講`、`○○休講`、`休み` | 休講 |
| `学園祭準備`、`宿泊研修`、`全員登校日`、`企業説明会` | 行事 |
| `時間は追って連絡` | 未定（メモとして表示） |
| `X` / `Y` / `Z` | 選択科目グループの枠。ファイル上の表記のまま取り込み、中身（科目・担当・教室・所属学生）は教員が入力する（§9.2-6） |
| 空欄 | 授業なし |

- 結合セルや改行の位置がずれても読めるよう、「コマ見出しの行」「コース名の行」を目印に探す。

### 7.3 検証と失敗時の動き
- 週が1つも見つからない、コマ見出しが4つそろわない、日付が読めない、などの場合は**失敗**とする。
- 失敗したときは、前回のデータをそのまま残し、通知は送らない。`schools/{domain}.sync` に失敗の理由を記録し、管理者に1回だけ知らせる。
- 解析はファイル形式ごとの「アダプター」に分ける（第3段階で年間予定表や他校の形式を追加しやすくするため）。

## 8. 同期と変更通知

- 実行：Cloud Scheduler で毎日 **8:00 と 17:00（Asia/Tokyo）**。管理者画面から手動実行もできる。
- ファイルの更新日時が前回と同じなら、ダウンロードせずに終わる。
- 比較の単位：`クラス × 日付 × コマ`。科目・担当・教室・メモ・状態のどれかが変わったら「変更」とする。
- 通知するのは**今日以降**の変更だけ。過去の週の修正は通知しない。
- 1回の同期で、クラスごとに通知を1つにまとめる。
  - 例：「1年・農業：10/29（木）3・4限 英語 → 休講 ほか1件」
- 通知先：そのクラス（学校ドメイン・学年・コース）の学生。
- プッシュ通知が届くのはスマホアプリ（Android/iOS）だけ。Web・デスクトップでは、同期のたびに更新する「最近の変更」（`school_changes`）をアプリ内で表示する（§11.1）。
- **重複通知の防止**：教員の手動入力（`school_overrides`）によってすでに即時プッシュ通知が送信された `(クラス × 日付 × コマ)` については、その後の定期同期で同じ変更が Excel 側から検出されても、二重にプッシュ通知を送らない。

## 9. 教員入力（第2段階）

学校ファイル（Excel）の定期同期（8:00 / 17:00）では間に合わない当日の急な変更（休講・教室変更・補講）や、教員からの課題配布・お知らせ連絡を、教員が直接入力して即座に学生へ届ける仕組み。

### 9.1 機能一覧
1. **授業の変更（休講・教室変更・補講・メモ）**：対象コマを選んですぐに公開。即時プッシュ通知を送る。
2. **課題の配布**：クラス・科目・締切日時・説明を指定して配布。学生の課題一覧に自動連携。
3. **お知らせ（連絡ボード）**：クラスまたは学年全体への伝達事項。
4. **確認状況（既読集計）**：お知らせや急な連絡を読んだ学生の人数・比率（例：25/28人確認）。
5. **選択科目グループ（X / Y / Z）の登録**：教員が分けたグループごとに、科目・担当・教室と所属する学生を登録する。

### 9.2 画面構成と操作の流れ

#### 1. 時間割編集画面（PC・Webブラウザ版）
- **レイアウト**：週カレンダー形式のマトリクス表（デザイン案「時間割の編集（PC）」準拠）。
  - ヘッダー：対象学年（1年/2年）およびコース（農業/観光）の切り替えタブ、週移動ボタン（前週・今週・翌週）。
  - テーブル：縦軸にコマ（1・2限〜7・8限、時刻表示付き）、横軸に月〜金の日付。
  - セル表示：科目名、担当教員、教室、現在の状態（通常 / 休講 / 変更 / メモ）を色分けバッジで表示。
  - 操作：コマをクリックすると、画面右側の「編集パネル」が開き（表を隠さない）、1分以内に入力・公開できる（§11.2-3）。

#### 2. アクション別入力フロー（編集パネル／スマホでは下から出るシート）
- **休講の登録**：
  1. 対象コマを選択 → 状態「休講」を選択。
  2. 理由・学生への伝達事項（例：「自習」「レポート課題あり」など）を任意入力。
  3. 「休講を公開」をクリック → Firestoreの `school_overrides` に即時保存。
  4. Cloud Functionsが該当クラスの学生に即時FCMプッシュ通知を配信（例：「【休講】本日 3・4限 IT概論2」）。
- **教室変更の登録**：
  1. 対象コマを選択 → 状態「教室変更」を選択。
  2. 新しい教室名（例：「第2PC室」）を入力。
  3. 「変更を公開」をクリック → 即時通知（例：「【教室変更】本日 5・6限 簿記2：102教室 → 第2PC室」）。
- **補講・振替の登録**：
  1. 空きコマまたは振替先コマを選択 → 「補講」を選択。
  2. 科目名（`subject`）、担当教員（`teacher`）、教室（`room`）、メモを入力して公開 → 即時通知。
- **授業メモ・追記事項**：
  1. 状態は通常のまま、メモ欄（例：「電卓持参」「小テスト実施」）を入力して保存。

#### 3. 課題配布画面（配布・進捗連携）
- **入力項目**：対象クラス（学年×コース、または複数選択）、科目名、課題タイトル、提出期限（日時）、詳細説明。
- **配布の流れ**：
  1. 教員が内容を入力し「課題を配布」を実行 → `school_assignments` に登録。
  2. 対象クラスの全学生の端末にプッシュ通知（「【新しい課題】IT概論2：レポート提出（期限: 11/5）」）。
  3. 学生アプリの「課題」タブに自動追加される。
  4. 学生は自分のアプリ上で進捗（未着手・進行中・完了）を更新する（学生個人の `assignments` レコードと連携）。
  5. 配布課題の進み具合は、学生の個人データ（`assignments`）とは別に `school_assignment_progress` に保存する（学生がアプリで更新すると、サーバーが両方を更新する）。
  6. 教員画面：集計（完了率・人数）と、**学生ごとの一覧（だれが未着手・進行中・完了か）**を表示する。
  7. 学生側：自分の進み具合だけが見える。**他の学生がだれ完了したかは見えない**（集計の数字も学生には表示しない）。
  8. 学生への説明：配布課題を初めて受け取ったとき、「この課題の進み具合は担当の先生に表示されます」と1回表示する。学生が自分で追加した課題は、これまで通りだれにも見えない。

#### 4. お知らせボード（連絡掲示板）
- **対象指定**：学年全体（1年生全員など）、または特定クラス（1年農業など）。
- **緊急度設定**：通常連絡 / 緊急連絡（緊急時は強調バッジ＋優先プッシュ通知）。
- **既読確認**：学生がアプリでお知らせを開いた際、`school_notice_reads` に記録。他の学生からは誰が読んだか閲覧できず、教員および本人のみが確認できる。教員画面には全体の集計（「既読 22 / 28名 (78%)」）が表示される。

#### 5. モバイル教員画面（スマートフォン簡易版）
- PCを開けない現場（実習場、教室移動中、出先など）からでも即座に操作できるレスポンシブ画面。
- 「今日・明日の自分の授業」がカード形式で一覧表示され、ワンタップで「休講」「教室変更」の登録・通知が可能。

#### 6. 選択科目グループ（X / Y / Z）の登録
- 学校ファイルでは、選択科目のコマが `X` / `Y` / `Z` とだけ書かれている。グループ分けは教員が行っているため、中身は教員が入力する。
- 入力項目：グループ（X / Y / Z）、学年、グループ名（例：日本語 上級）、科目、担当、教室、所属学生（学校アカウントのメールで選択）。
- 学校ファイルの `X` のコマには、学生ごとに自分のグループの科目・教室が表示される。グループ未登録の学生には「選択科目 X（グループ未登録）」と表示する。
- グループ分けが学期の途中で変わった場合は、教員が所属を変更する（変更した学生に通知）。

### 9.3 学校ファイル（Excel同期）との競合・解消ルール

教員が入力した手動変更（`school_overrides`）と、定期同期される学校ファイル（Excel）の内容は以下のルールで解決する。

1. **基本表示優先度**：
   - 最優先：**教員入力（未解消の override）**
   - 2番目：**学校データ（Excel同期データ）**
   - 個人枠：**学生の手入力（個人スケジュール）**（学校データと重ねて表示し、上書きはしない）

2. **Excelとの突き合わせと自動解消（8:00 / 17:00 の同期時）**：
   - 同期処理（`syncSchoolTimetable`）実行時、有効な教員入力と同じ `(クラス, 日付, コマ)` のExcelセルを比較する。
   - **一致（反映完了）**：
     - Excel側のセルにも同様の変更（「休講」や変更後の教室）が反映されていた場合、教員入力レコードの `resolved` を `true` に更新する。
     - 学生アプリの表示元は自動的に「学校データ（Excel）」へ一本化される（学生の見た目や通知に不自然な変化は起きない）。
   - **不一致（未反映・競合）**：
     - Excel側が通常授業のまま、あるいは別の内容になっている場合、学生アプリには引き続き**教員入力を最優先**で表示し続ける（現場の教員の即時判断を尊重）。
     - 教員管理画面上に差分アラート（「学校ファイル未反映：ファイル上は通常授業です」）を表示し、教員が「入力内容を維持」または「ファイルに合わせる」を選択できる。

3. **期限切れとアーカイブ**：
   - 該当コマの終了時刻から24時間が経過した override は、自動的にアクティブ一覧からアーカイブへ移行し、通常表示ロジックから外れる。

## 10. データ設計（Firestore）

| コレクション | 主な項目 | 読み取り | 書き込み |
|---|---|---|---|
| `schools/{domain}` | name, file{id, name, modifiedTime}, periods[{key, label, start, end}], grades, courses, admins[], teachers[], sync{lastRunAt, status, error} | 同じドメインのユーザー | サーバー、管理者（一部） |
| `school_secrets/{domain}` | refreshToken, linkedBy, linkedAt | なし | サーバーのみ |
| `school_days/{domain}_{学年}_{コース}_{yyyyMMdd}` | date, slots[{period, subject, teacher, room, note, status}], hash | 同じドメインのユーザー | サーバーのみ |
| `school_overrides/{id}` | domain, grade, course, date, period, kind, subject, teacher, room, note, createdBy, createdAt, resolved, resolvedAt | 同じドメインのユーザー | 教員 |
| `school_assignments/{id}` | domain, grade, course, subject, title, dueAt, description, stats{totalCount, completedCount, inProgressCount, notStartedCount}, createdBy, createdAt | 同じドメインのユーザー | 教員 |
| `school_notices/{id}` | domain, target{grade, course}, title, body, priority, createdBy, createdAt | 同じドメインのユーザー | 教員 |
| `school_notice_reads/{domain}_{noticeId}_{uid}` | readAt | 教員および本人のみ | 本人のみ |
| `school_assignment_progress/{assignmentId}_{uid}` | domain, assignmentId, uid, status, progress, updatedAt | 教員および本人のみ | サーバーのみ（学生の更新を経由） |
| `school_elective_groups/{id}` | domain, grade, slotLabel(X/Y/Z), name, subject, teacher, room, memberEmails[], updatedBy | 同じドメインのユーザー（所属情報は教員と本人のみ） | 教員 |
| `school_changes/{domain}_{学年}_{コース}` | items[{date, period, subject, what, at}]（新しい順に最大30件） | 同じドメインのユーザー | サーバーのみ |
| `users/{uid}` | 既存項目＋ schoolDomain, role | 本人 | 本人（role はサーバーのみ） |

- 課題の進み具合は、今の `assignments`（本人のみ）に `sourceId`（配布課題のID）を付けて保存する。配布課題そのものは共有、進み具合は個人のまま。
- 学年・コースは、学校情報フォームにすでにある `grade`・`course` を使う。学校データがある場合、コースは自由入力ではなく、ファイルから読み取った一覧（農業／観光）から選ぶ。

## 11. アプリ側の変更（第1段階）

1. ログイン：学校ドメインのアカウントなら `schoolDomain` を設定し、学校情報フォームで学年とコースを選ぶ。
2. 時間割画面：週の日付ごとに学校データを表示する（今の週切り替え・日付表示を利用）。手入力の授業は「自分」として一緒に表示する。
3. コマの時刻：学校の `periods` を使う。授業前のリマインダーもこの時刻で計算する（今は 3限＝13:00 だが、この学校では 13:10）。
4. 表示：休講は二重線、教室変更は新しい教室を表示、行事は帯で表示する。
5. 設定画面：連携状態（最終同期の時刻）を表示する。

6. 「最近の変更」：同期で見つかった変更（休講・教室変更など）を新しい順に一覧表示する。前回見た後の変更には印を付ける（最後に見た時刻は端末に保存）。全プラットフォーム共通。

### 11.1 対応プラットフォーム（スマホ・Web・デスクトップ）

| 機能 | スマホアプリ（Android / iOS） | Web（PC・スマホのブラウザ） | デスクトップ |
|---|---|---|---|
| 学校アカウントでログイン | ○（Google ログイン） | ○（Google ログイン：ポップアップ） | Web 版を使う |
| 学校の時間割の表示 | ○ 日ごとのタブ | ○ 画面幅 600 以上は週の表（コマ × 月〜金）、それ未満は日ごとのタブ | Web 版を使う |
| 変更のプッシュ通知 | ○（FCM） | ×（アプリ内の「最近の変更」で表示） | Web 版を使う |
| 授業前リマインダー | ○（端末内の通知） | × | Web 版を使う |
| ファイル連携ページ | — | ○（PC 推奨） | Web 版を使う |
| 教員入力（第2段階） | ○ 簡易版 | ○ 本体（PC の週の表で編集） | Web 版を使う |

- **デスクトップは Web 版で提供する。** Firebase の Flutter 用ライブラリ（FlutterFire）は Linux に対応しておらず、Google ログイン（google_sign_in）もデスクトップに対応していないため、ネイティブのデスクトップアプリでは学校の Google アカウントでログインできない。PC では Chrome / Edge で Web 版を開き、「アプリとしてインストール」（PWA）すればデスクトップアプリのように使える。
- **Web の通知**：Web プッシュには Service Worker（`firebase-messaging-sw.js`）と VAPID キーが必要で、現在のアプリには入っていない。第1段階では「最近の変更」で代わりにし、Web プッシュは要望があれば後の段階で追加する。
- **週の表（Web・タブレット）**：学校の時間割ファイルと同じ形（縦にコマ、横に月〜金）で表示する。休講は二重線、教室変更は新しい教室、行事は帯、自分で追加した授業は「自分」の印を付けて同じ表に入れる。週の切り替えは今のボタンをそのまま使う。
- **画面幅の基準**：今のアプリの基準（600 以上をタブレット、1200 以上をデスクトップ）に合わせる。1200 以上では表の横に「最近の変更」を並べて表示する。

### 11.2 画面構成：スマホとPC

#### 11.2-1 共通のルール（どの画面でも同じ）
- **同じ名前・同じ見た目**：休講は二重線＋「休講」、教室変更は新しい教室を強調、行事は帯、未定は「未定」、選択科目は「選択科目 X」、自分で追加した授業は「自分」。スマホでもPCでも同じ表示にし、覚え直しをなくす。
- **役割で最初の画面が決まる**：学生は「ホーム」、教員は「教員ホーム」から始まる。教員・管理者だけの機能は、権限のない人には表示しない（ボタンを押してから「権限がありません」と出さない）。
- **よく使う操作は3タップ以内**：学生は「今日の授業」と「最近の変更」をホームで見られる。教員は「授業 → 休講 → 公開」の3タップで休講を出せる。
- **スマホとPCの役割分担**：スマホは「見る・すぐ知らせる」、PCは「まとめて入力・管理する」。同じ機能は両方にあるが、PCだけの機能（ファイル連携・教員登録・グループ分けなど、入力が多いもの）はスマホに入れない。

## 12. セキュリティ・プライバシー

- サーバーが持つのは、選ばれた1ファイルだけを読めるトークンで、`school_secrets` は Firestore のルールで全面的に読み書き禁止にする。
- 学校データは同じドメインのユーザーだけが読める。
- 時間割には教員の名前が含まれるが、もともとドメイン内に共有されている情報であり、表示範囲も同じドメインに限る。AI への送信には含めない（今の方針を維持）。
- 配布課題の進み具合は、担当の教員と本人だけが見られる。学生どうしではだれが完了したか分からない。学生には受け取り時に「先生に表示される」ことを明示する。学生が自分で追加した課題は、教員にも見えない。
- 選択科目グループの所属（だれがどのグループか）は、教員と本人だけが見られる。
- 解析テスト用のファイルは、教員名を仮名に置き換えたものをリポジトリに置く。実ファイルは置かない。
- **学校（ファイルの所有者である先生・教務）の許可を得てから連携する。**

## 13. 未決事項と決定事項

1. **時間割ファイルの利用許可**：【決定】まずは開発・検証（プロトタイプ段階）を先行し、動作確認ができた段階で所有者の先生・教務に実機デモを提示して本番連携の了承を得る（開発段階では個人情報を伏せたテストデータで運用）。
2. **学校管理者**：【決定】検証期間は開発者本人の学校アカウント。運用開始時に教務へ引き継ぐ。
3. **教員の登録**：【決定】学校管理者がメールアドレスで1人ずつ登録する。まず1〜2名で試す。
4. **`X` / `Y` / `Z`**：【決定】教員が分けた選択科目グループ。ファイルの表記のまま取り込み、グループの中身と所属学生は教員が入力する（§9.2-6）。
5. 学校の管理者設定で、外部アプリの Google 連携が許可されているか（許可されていなければ方式Cに切り替え）。
6. 年間予定表など、第3段階で取り込みたいファイルの一覧と保存場所。
7. Google の OAuth 同意画面の公開に必要なプライバシーポリシーのURL（`docs/privacy-policy.html` を公開して使う）。
8. **配布課題の進み具合**：【決定】教員は学生ごとの一覧まで見られる。学生には他の学生の状況は見えない（集計も非表示）。受け取り時に学生へ明示する（§9.2-3、§12）。

## 14. テスト

- 解析：仮名化した実ファイルで、週数・クラス数・コマ時刻・状態判定（通常／休講／行事／未定）を確認する単体テスト。形式が崩れたファイルで「失敗」になり、前回データが残ること。
- 比較：変更なし／教室変更／休講追加／過去の週だけの修正 で、通知の有無と文面を確認する。
- ルール：Firestore エミュレーターで、他ドメインから読めない・学生が書けない・`school_secrets` に誰もアクセスできないことを確認する。
- 端末：エミュレーターで同期後の表示、通知の受信、授業前リマインダーの時刻（13:10 基準）を確認する。
- Web：`flutter build web` 版を 390 / 768 / 1440 の幅で開き、日ごとのタブ（390）と週の表（768・1440）、1440 での「最近の変更」の横並び、ログインから表示までを確認する。
